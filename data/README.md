# 곁이음 복지사업 데이터

독거노인 복지서비스 탐색 MVP를 위한 2026년 공식 안내 기반 정규화 데이터입니다. 브라우저용 검색·추천 함수는 `../frontend/welfare-search.js`에 있습니다.

## 구성

단일 복지사업 JSON은 사용하지 않습니다. `manifest.json`은 파일 위치와 개수만 알려주며 실제 사업 데이터는 `departments/` 아래 12개 파일에 나뉘어 있습니다.

| 파일 | 담당 영역 | 개수 |
|---|---|---:|
| `departments/mohw-elderly-care.json` | 보건복지부 노인 돌봄·요양 | 6 |
| `departments/income-living-support.json` | 소득·연금·생활지원 | 6 |
| `departments/mohw-health-medical.json` | 치매·수술·치과·의료비 | 6 |
| `departments/molit-housing.json` | 주거급여·공공임대·주거상향 | 6 |
| `departments/energy-utility-support.json` | 냉난방·전기·가스·수도·효율개선 | 6 |
| `departments/local-government-welfare.json` | 서울·경기 지역 자체사업 | 6 |
| `departments/national-preventive-health.json` | 검진·예방접종·치과·보험료 경감 | 6 |

기준일은 `2026-09-04`, 공통 스키마 버전은 `2.0.0`입니다.

## 레코드 구조

모든 부서 파일과 72개 레코드는 같은 키 구조를 사용합니다.

| 필드 | 의미 |
|---|---|
| `id` | 연도와 지역이 포함된 고유 ID |
| `name`, `summary` | 앱 카드에 표시할 쉬운 사업명과 설명 |
| `managingOrganization` | 제도 또는 서비스를 운영하는 기관 |
| `managingDepartment` | 공식 안내에서 확인한 담당 부서 또는 담당 기능 |
| `status` | 현재 수록 상태. 이번 데이터는 모두 `ACTIVE` |
| `coverage` | `전국`, `서울특별시`, `경기도`, `전국-지자체별상이` 등 지역 범위 |
| `category` | 앱의 대표 지원 분류 하나 |
| `relatedCategories` | 복합 서비스를 찾기 위한 보조 분류 |
| `serviceTypes` | 실제 제공 방식 |
| `eligibility` | 앱용 조건과 원문 조건 |
| `benefits` | 쉬운 문장으로 정리한 지원 내용 |
| `requiredDocuments` | 신청 준비 화면에 표시할 서류 |
| `application` | 모집 방식, 기한, 신청방법, 기관, 연락처 |
| `source` | 공식 원문, 기준연도, 확인일 |
| `matchTags` | 생활상황 질문과 추천 점수를 연결하는 태그 |

## `eligibility` 규칙

- `minAge`, `maxAge`: 숫자로 단정할 수 있을 때만 입력합니다.
- `livingAlone`: `true`이면 독거가 필수, `false`이면 독거 대상이 아님, `null`이면 필수가 아니거나 가구유형별 조건이 복잡하다는 뜻입니다.
- `assistanceNeed`: `LOW`, `MEDIUM`, `HIGH` 중 추천 가능한 필요도입니다. 빈 배열은 필요도 제한이 없다는 뜻입니다.
- `incomeTypes`: 소득·수급자격을 정규화한 코드입니다. 여러 값은 원칙적으로 후보 조건이며, AND 조건은 `conditions` 문장을 함께 확인합니다.
- `conditions`: 앱이 자동 확정하면 안 되는 공식 세부 조건과 중복 제한입니다.

사용자 정보가 없거나 프로그램 값이 `null`이면 탈락시키지 않고 `NEEDS_CONFIRMATION`으로 처리하는 것이 안전합니다.

## 대표 분류

| 값 | 의미 |
|---|---|
| `CARE` | 방문돌봄·가사·통합 사례관리 |
| `LIVING` | 연금·현금·바우처·공공요금 |
| `MEDICAL` | 검사·수술·치료·치과 비용 |
| `MEAL` | 경로식당·도시락·밑반찬 |
| `MOBILITY` | 병원동행·외출·교통 |
| `HOUSING` | 임차료·공공임대·집수리 |
| `SAFETY` | 응급장비·안부확인·낙상 예방 |

`category`는 결과 카드의 대표 분류이고 `relatedCategories`도 사용자 `needs` 점수에 포함해야 복합서비스가 누락되지 않습니다.

## 소득 코드 사용법

자주 쓰는 값은 다음과 같습니다.

- `ANY`: 소득 제한 없음
- `BASIC_LIVELIHOOD_ANY`: 생계·의료·주거·교육급여 중 해당 자격
- `BASIC_LIVELIHOOD_LIVING_OR_MEDICAL`: 생계 또는 의료급여
- `NEAR_POVERTY`: 차상위계층
- `BASIC_PENSION_RECIPIENT`: 기초연금 수급자
- `BASIC_PENSION_SELECTION_THRESHOLD`: 기초연금 선정기준액 이하
- `MEDIAN_INCOME_32_OR_LESS` 등: 기준 중위소득 해당 비율 이하
- `LOCAL_LOW_INCOME`, `LOCAL_ORDINANCE`: 지자체 판단이나 조례 적용
- `PUBLIC_HOUSING_INCOME_LIMIT`: 공급유형별 공공임대 소득·자산 기준

이름만으로 판정하기 어려운 `EMERGENCY_WELFARE_INCOME_LIMIT`, `SEOUL_ASSET_LIMIT` 등은 사용자가 모른다고 가정하고 추가 확인 조건으로 보여주는 편이 좋습니다.

## 추천 필터 순서

1. `manifest.json`에서 부서 파일 목록을 읽습니다.
2. 각 파일의 `programs` 배열만 합쳐 메모리에 올립니다.
3. `coverage`와 사용자 지역이 명확히 불일치하는 사업을 제외합니다.
4. 연령이 명확히 미달하거나 초과한 사업만 제외합니다.
5. `category`, `relatedCategories`, `matchTags` 일치도를 점수에 반영합니다.
6. 수급자격이 확인되면 가점을 주고 모르면 `NEEDS_CONFIRMATION`으로 둡니다.
7. `conditions`의 개별심사·등급·최근 위기·중복 제한을 결과 카드의 확인사항으로 표시합니다.

## 예시 사용자

서울에 사는 만 78세 독거 어르신이 외출과 식사 준비에 도움이 필요하다면 다음을 우선 후보로 둘 수 있습니다.

1. 노인맞춤돌봄서비스
2. 서울 돌봄SOS
3. 서울시 저소득 어르신 급식지원
4. 서울시 병원 안심동행서비스
5. 의료·요양 등 지역돌봄의 통합지원
6. 응급안전안심서비스

이 가운데 돌봄SOS는 최근 발생한 돌봄 공백, 급식지원은 소득과 결식 우려, 응급안전안심서비스는 실제 거주형태를 추가 확인해야 합니다.

## 갱신 원칙

- 연도별 금액과 소득 기준은 `basisYear`가 바뀔 때 다시 확인합니다.
- 모집공고형 사업은 마감 후 삭제하지 말고 `status: CLOSED`와 실제 `deadline`을 남깁니다.
- 중앙 안내와 지자체 공고가 다르면 전국 공통 자격은 주무부처, 지역 접수기간과 물량은 지자체 공고를 우선합니다.
- 언론·블로그는 발굴에만 사용하고 `source.url`에는 정부·지자체·공공기관 원문을 넣습니다.
- 정확한 금액이 원문에서 확인되지 않으면 과거 금액을 재사용하지 말고 `benefits`에 담당기관 확인 필요라고 기록합니다.
- 이 데이터는 후보 검색용이며 신청 자격을 확정하는 자동 판정 자료가 아닙니다.
